Awal perjalanan

Latar Belakang & Konsep Dasar

Berangkat dari satu pertanyaan: bagaimana teknologi dapat membantu manusia mengelola kehidupan secara utuh, bukan hanya menyelesaikan satu tugas?

⌕

Latar Belakang

Aktivitas kehidupan sehari-hari tersebar di banyak aplikasi: keluarga, keuangan, pendidikan, mobilitas, komunitas, dan aktivitas lainnya. Informasi terfragmentasi membuat pengguna harus menghubungkan sendiri konteks dan prioritasnya.

✧

Konsep Dasar

LiNo dirancang sebagai platform pengelolaan kehidupan personal yang menghubungkan data dan kemampuan dari berbagai pilar, lalu menggunakan AI untuk memahami konteks dan membantu pengguna mengambil langkah berikutnya.

◈
Bukan sekadar super app yang ditempeli AI.DNA Engine adalah inti kecerdasan; pilar menjadi sumber data otoritatif, konteks, dan kapabilitas dengan persetujuan pengguna.

Nama LiNo merujuk pada gagasan Life Now / Life In One: membantu menyatukan berbagai konteks kehidupan dalam satu ekosistem yang saling memahami. Antarmuka chat dapat menjadi salah satu cara berinteraksi, tetapi bukan definisi utama produk.

03
Mengapa LiNo dibangun

Masalah & Solusi

Fokusnya bukan menambah aplikasi, tetapi mengurangi fragmentasi konteks dan beban koordinasi yang ditanggung pengguna.

Tantangan saat ini

  • Data tersebar di aplikasi dan layanan berbeda.
  • Pengguna mengulang input dan menjelaskan konteks.
  • Agenda, relasi, dan kebutuhan tidak saling terhubung.
  • Rekomendasi sering terlepas dari kondisi nyata.
  • Tindakan lintas layanan memerlukan koordinasi manual.

Pendekatan LiNo

  • Data otoritatif dari pilar dengan consent.
  • Personal Life Model untuk konteks pengguna.
  • AI memahami prioritas dan hubungan antaraktivitas.
  • Planning dan rekomendasi yang dapat dievaluasi.
  • Orkestrasi tindakan melalui layanan terotorisasi.

Contoh: agenda keluarga, kebutuhan mobilitas, dan aktivitas pendidikan dapat saling memengaruhi. DNA Engine membantu menghubungkan konteks tersebut sehingga pengguna tidak perlu menyatukannya secara manual dari banyak aplikasi.

Prinsip operasional DNA Engine

Fakta ≠ Inferensi

Data sumber, hasil inferensi AI, dan tindakan yang diizinkan harus dibedakan dengan jelas.

Proaktif, tidak selalu memanggil model

Event diproses sesuai aturan dan kebutuhan. Model AI dipanggil ketika memberi nilai tambah, bukan untuk setiap event.

Human approval

Evaluasi hasil

Sistem belajar dari outcome dan koreksi pengguna, bukan hanya menghitung jumlah percakapan.

10
Gerbang layanan

LiNo Gateway

Lapisan akses dan orkestrasi request yang menjaga kontrak, kebijakan, serta efisiensi komunikasi antarlayanan.

Rust Data Plane

Target untuk jalur request ber-throughput tinggi: routing, connection handling, async fan-out/fan-in, dan pemrosesan yang terukur.

Go Control Plane

Pengelolaan konfigurasi, kebijakan, registrasi, dan administrasi gateway.

Aggregation Engine

Rancangan aggregation engine menggunakan definisi DAG/graph untuk menjalankan pemanggilan layanan, dependency, batas waktu, dan penggabungan hasil secara deterministik. Setiap node dapat memiliki aturan otorisasi dan budget sendiri.

Async fan-out / fan-inTimeout budgetTyped resultPartial failureIdempotent retry

Retry hanya dilakukan untuk operasi yang aman atau memiliki idempotency key. Kegagalan layanan tidak boleh disamarkan sebagai nilai sukses palsu.

11
Fondasi data

LiNoDB

Konsep database platform dengan satu endpoint logis, routing SQL, dan pengelolaan shard yang transparan bagi layanan.

Rust SQL Router

PostgreSQL wire protocol, routing query ke shard, koneksi, dan jalur data yang dirancang efisien.

Go Control Plane

Metadata, administrasi cluster, shard map, lifecycle, dan operasi pengendalian.

Metadata & HA

etcd untuk metadata/routing state; PostgreSQL dengan Patroni untuk HA; pgBackRest untuk backup dan PITR.

Virtual Sharding

Konsep 64 virtual shards, routing, pemindahan shard online, dan rebalance yang harus dijaga konsistensinya.

Prinsip penting

SQL Gateway LiNoDB berbeda dari LiNo API Gateway. Database gateway menangani protokol dan routing SQL; API Gateway menangani request aplikasi dan kontrak layanan. Operasi shard movement memerlukan fencing, metadata konsisten, observability, serta pengujian recovery sebelum digunakan pada beban produksi.

12
Eksekusi proses jangka panjang

LiNo Workflow Engine

Menjalankan proses durable lintas layanan, termasuk timer, retry, saga, approval, dan pemulihan setelah gangguan.

Rust Execution Runtime

Tokio event loop, worker pool, correlation engine, state machine, scheduler durable, timer/retry, saga, persistence, dan recovery.

Go Control Plane

Admin API, pengelolaan definisi workflow, konfigurasi, dan activity workers Go yang sudah ada tetap dapat digunakan.

Reliability model

Lease + heartbeatFencing tokenIdempotencyBounded worker poolGraceful drainCrash recovery

State workflow disimpan secara durable. Kafka digunakan untuk event dan notifikasi; transactional outbox/inbox dapat dipakai untuk menjaga konsistensi publikasi. Redis bersifat opsional untuk wake-up atau cache. Transaksi database dijaga singkat—hindari menahan transaksi selama inference AI, menunggu approval, atau memanggil API eksternal.

Catatan: zero-downtime membutuhkan redundansi dan dependency yang tersedia. Crash recovery saja tidak menjamin layanan selalu tanpa downtime.

13
Komunikasi langsung

LiNo Realtime

Kanal komunikasi real-time untuk aplikasi yang sedang aktif, berbeda peran dari push notification.

Rust WebSocket Service

Menangani koneksi, event loop, fan-out, subscription, reconnect, dan pengelolaan koneksi secara efisien.

Event-driven

Event berasal dari layanan domain/Kafka, lalu dikirim ke sesi aktif sesuai identitas, subscription, dan otorisasi.

Realtime cocok untuk update langsung ketika aplikasi aktif. Ketika aplikasi berada di background atau tidak aktif, pengiriman dapat dialihkan melalui FCM. Reconnect dan pemulihan state tetap perlu mengacu pada data durable, bukan menganggap setiap pesan pasti diterima.

Platform operasional

Kubernetes + LiNo Service Platform

Kubernetes menjadi orchestrator; LiNo Service Platform menjadi lapisan pengelolaan layanan di atasnya.

Kubernetes

Menjalankan workload, scheduling, service discovery, health checks, rollout, dan mekanisme orkestrasi container.

Durable Handoff Context
